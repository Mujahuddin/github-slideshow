## THE 6 DIFFICULTY LEVELS (used throughout every chapter)

- **Level 1 — Beginner:** pattern introduced with the simplest possible example.
- **Level 2 — Easy:** direct application of the pattern.
- **Level 3 — Medium:** pattern combined with one twist (e.g., sliding window + hashmap).
- **Level 4 — Hard:** pattern combined with a second pattern, or a non-obvious state space.
- **Level 5 — Senior Interview:** problem statement is ambiguous on purpose — you must clarify requirements, like a real interview.
- **Level 6 — Production-oriented:** the "pattern" is a real system component (cache, rate limiter), not a leetcode-style puzzle.

## HOW TO USE THIS BOOK (Pattern Recognition Method)

For every new problem, before writing code, ask in order:
1. What is the **input shape**? (array, string, tree, graph, stream of events?)
2. What is being **asked**? (existence, count, optimal value, all combinations?)
3. Does the input have **exploitable structure**? (sorted? bounded range? small alphabet?)
4. What's the **brute force**, and what's its complexity?
5. Which **known pattern** removes the redundant work the brute force does?

This 5-question method is repeated explicitly in every chapter until it
becomes automatic — that automaticity IS the mastery goal of this book.
